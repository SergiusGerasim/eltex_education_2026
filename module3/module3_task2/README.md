# Формулировка задания 2:
#очереди_сообщений #System_V #сигналы

>Разработать программу, реализующую модель "Издатель-Брокер-Подписчик".

- Процесс может быть запущен либо в роли брокера сообщений, либо в
роли издателя, либо в роли подписчика.
- При запуске с ключом -b процесс работает как брокер сообщений. Он
создает очередь сообщений и считывает из нее сообщения с приоритетом,
равным 1. В сообщении указана тема (topic) и его содержимое (payload).
Сообщение пересылается получателям (подписчикам), которые
заинтересованы в получении сообщений с данной темой. Для этого брокер
хранит список pid процессов-подписчиков и тем, на которые они подписаны
(один подписчик может подписаться на несколько тем). Также брокер хранит
список процессов-издателей, чтобы можно было уведомить их о завершении
работы.
- Если уже имеется очередь сообщений (другой процесс уже запущен в
роли брокера), то новая программа-брокер сообщает об этом и завершается.
Количество процессов-издателей и подписчиков не ограничено.
- При запуске с ключом -p процесс работает в режиме издателя. Он
отправляет в очередь сообщения с указанной темой (тему указывать в
аргументах запуска). В начале текста сообщения должна быть строка
"send,<pid>,<topic>" Сообщения могут формироваться любым способом:
генерироваться автоматически, вводиться пользователем, читаться из файла
и др. Приоритет исходящего сообщения задается равным 1
- При запуске с ключом -s процесс работает в режиме подписчика. Он
читает сообщения из очереди, приоритет которых равен его pid, и выводит
на экран информацию о полученном сообщении. Чтобы сообщить брокеру о
подписке на сообщения с определенной темой, подписчик отправляет в
очередь сообщение с приоритетом 1 и текстом
"subscribe,<pid>,<topic>". При завершении работы подписчик уведомляет брокера
сообщением "unsubscribe,<pid>,<topic>". Список тем указывается в аргументах запуска процесса.
- При завершении работы брокера он перестает помещать в очередь
сообщения для рассылки и рассылает процессам сигналы о завершении
SIGINT. При освобождении очереди или по таймауту брокер удаляет очередь
и завершает работу. Процессы-издатели и подписчики должны завершиться,
если получен сигнал или очередь стала недоступной.
