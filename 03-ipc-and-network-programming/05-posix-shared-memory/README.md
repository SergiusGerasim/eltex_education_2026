# Формулировка задания 5

#семафоры #разделяемая_память #POSIX #имитация_односвязного_списка

- Выполнить задание 4 с использованием семафоров + разделяемой памяти POSIX.

## Реализация

Производитель создаёт именованные POSIX-объекты:

- `/module3_task5_shm` — разделяемая память;
- `/module3_task5_sem` — семафор, защищающий общую структуру.

Разделяемая память создаётся через shm_open, получает размер через ftruncate и отображается в адресное пространство через mmap. Потребители открывают тот же объект, определяют размер через fstat и подключаются посредством mmap.

Список хранит относительные смещения вместо указателей, поэтому процессы могут отображать общую память по разным виртуальным адресам. Производитель добавляет массивы, а потребители независимо забирают готовые блоки, вычисляют минимум и максимум и отмечают их обработанными.

## Сборка и запуск

```sh
make
./build/module3_task5 producer 4096 1 2 10 20 -100 100 &
./build/module3_task5 consumer 2 &
./build/module3_task5 consumer 2 &
wait

```

Можно запустить несколько потребителей. Сначала запускается производитель, затем потребители. Полный формат аргументов выводится при ошибке запуска.

Производитель удаляет имена POSIX-объектов через `shm_unlink` и `sem_unlink` после обработки всех опубликованных блоков и выхода потребителей. Каждый процесс отдельно освобождает отображение и дескрипторы через `munmap`, `close` и `sem_close`.

## Отличия от варианта System V

| System V | POSIX |
|---|---|
| `ftok`, `key_t` | строковые имена с начальным `/` |
| `shmget` | `shm_open` и файловый дескриптор |
| размер задаётся в `shmget` | `ftruncate` после создания |
| `shmat` / `shmdt` | `mmap` / `munmap` |
| `shmctl(..., IPC_RMID)` | `shm_unlink` |
| `semget`, `semop`, `semctl` | `sem_open`, `sem_wait`, `sem_post` |
| поддерживается `SEM_UNDO` | автоматического отката захваченного семафора нет |

POSIX-объекты имеют файловую модель доступа и на Linux обычно видны в `/dev/shm`. Вызов `unlink` удаляет имя, но уже открытые дескрипторы и отображения продолжают работать до их закрытия — аналогично удалённому открытому файлу.
