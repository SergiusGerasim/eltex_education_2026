### Управление такси. 
- Есть опорный пункт – исходное приложение.
- Запускается один раз и привязано к терминалу, имеет CLI.
- В CLI должны быть команды
    - create_driver
    - send_task <pid> <task_timer>
    - get_status <pid>
    - get_drivers


- create_driver создает новый процесс (driver), который ожидает
команд от CLI. PID процесса будет использоваться для обращения к этому
driver.
- send_task <pid> <task_timer> создаст задачу для driver номер
pid и займет его на task_timer секунд. Если попытаться обратиться к
этому driver во время выполнения задания с помощью send_task, то
driver должен послать ошибку Busy <task_timer>. 
- По истечению task_timer секунд driver меняет свое состояние на Available.
- get_status <pid> показывает статус driver с номером pid. Может быть Busy <task_timer> либо Available.
- get_drivers показывает статусы и pid всех drivers запущенных из этого инстанса CLI.

- С таймерами нужно разобраться самостоятельно. 
- Процесс не должен ожидать заданное время в цикле while без полезных действий.
- Механизмы IPC, которые нужно использовать при решении этой задачи, задаются преподавателем! Способ мультиплексирования **нужно выбрать такой, который не использовался при решении задачи 7**.

- В 7м задании использовались способы мультиплексирования — poll и epoll
    - > Для этого задания необходимо использовать select

## Реализация

Управляющее приложение запускается один раз и работает в терминале. Каждый водитель создаётся отдельным процессом через `fork()` и подключается к родителю через отдельное TCP-соединение на `127.0.0.1`.

Для мультиплексирования используется `select()`:

- родитель одновременно обрабатывает stdin, listener, новые соединения и ответы водителей;
- водитель одновременно ожидает TCP-команду и окончание таймера задачи.

Таймер основан на `CLOCK_MONOTONIC`. Водитель не использует пустой цикл ожидания или `sleep()` на всё время задачи.

## Сборка

```bash
make
```

Исполняемый файл создаётся по пути:

```text
build/taxi_control
```

## Запуск

```bash
./build/taxi_control
```

Приложение не требует аргументов командной строки. TCP-listener привязывается к `127.0.0.1` и использует свободный порт, выбранный операционной системой.

## Команды

Создать водителя:

```text
create_driver
```

Пример ответа:

```text
Driver created: 12345
Driver connected: 12345
```

Назначить задачу на указанное количество секунд:

```text
send_task <pid> <task_timer>
```

Пример:

```text
send_task 12345 10
Driver 12345: Task accepted 10
```

Повторная задача занятому водителю не заменяет текущую:

```text
Driver 12345: Busy 7
```

Число после `Busy` — оставшееся время, округлённое вверх до целых секунд.

Получить состояние одного водителя:

```text
get_status <pid>
```

Получить состояния всех водителей этого экземпляра приложения:

```text
get_drivers
```

Если водители отсутствуют:

```text
No drivers
```

PID и `task_timer` должны быть положительными целыми числами в диапазоне `uint32_t`.

## Завершение

Приложение завершается при:

- `Ctrl+C` (`SIGINT`);
- `SIGTERM`;
- EOF в stdin (`Ctrl+D`).

При завершении родитель отправляет подключённым водителям `SHUTDOWN`. Процессы, которые не завершились за отведённое время, получают `SIGTERM`, после чего родитель собирает их через `waitpid()`.

`SIGCHLD` используется для своевременного удаления завершившихся водителей и предотвращения zombie-процессов.

## Тесты

Запустить весь набор:

```bash
make test
```

Доступны отдельные цели:

```bash
make test-protocol
make test-tcp-socket
make test-driver
make test-cli
make test-app
make test-signal-handler
```

Интеграционный тест приложения проверяет трёх водителей, состояния `Available` и `Busy`, аварийное завершение одного водителя, завершение по `SIGTERM` и немедленный EOF после `create_driver`.
